# java-url-shortener

Итоговый проект по курсу "Программирование на языке Java": консольный сервис сокращения ссылок с лимитом переходов и временем жизни.

## Возможности

- Сокращение длинного URL в короткую ссылку вида `clck.ru/c7cK8qB`
- Один и тот же URL у разных пользователей дает разные короткие ссылки
- Лимит переходов задает пользователь, после исчерпания ссылка блокируется
- Время жизни ссылки задается конфигом (по умолчанию сутки), по истечении ссылка удаляется сама
- Уведомления владельцу, если лимит исчерпан или ссылка протухла, с подсказкой поднять лимит или создать новую
- Пользователь без регистрации: UUID создается при первом `shorten` (или командой `user new`) и запоминается в файле
- Менять и удалять ссылку может только ее создатель
- Переход по короткой ссылке открывает исходный URL в браузере (`Desktop.browse`)

## Установка и запуск

Нужна только JDK 25. Maven ставить не надо: в репозитории есть Maven Wrapper (`mvnw`), он сам скачает нужную версию. Внешних библиотек в рантайме нет, JUnit подтягивается Maven только для тестов.

```bash
git clone https://github.com/KATEHOK/java-url-shortener.git
cd java-url-shortener
./mvnw package
java -jar target/url-shortener.jar
```

На Windows вместо `./mvnw` - `mvnw.cmd`.

Если в текущей директории лежит `shortener.properties`, он подхватывается сам (в корне репозитория такой файл есть, в нем все значения по умолчанию). Можно передать и другой конфиг первым аргументом, тогда используется он:

```bash
java -jar target/url-shortener.jar my.properties
```

`java -jar target/url-shortener.jar --help` (или `-h`) печатает строку запуска. Больше одного аргумента - ошибка.

Данные хранятся в `data/` относительно текущей директории: `links.tsv` - ссылки, `notices.tsv` - еще не показанные уведомления, `user.id` - UUID последнего пользователя. Поэтому после перезапуска ссылки, уведомления и пользователь сохраняются.

Консоль одна на всех: при старте загружается последний пользователь из `data/user.id`, и кто сядет за консоль, тот и будет им. UUID работает как ключ доступа к ссылкам, так что не оставляйте консоль другим, а свой UUID запишите. Если `data/user.id` сохранить не удалось, пользователь все равно остается текущим до выхода, а программа просит записать UUID самому.

## Команды

| Команда | Что делает |
|---|---|
| `shorten <url> [limit]` | создать короткую ссылку, `limit` - максимум переходов (по умолчанию из конфига) |
| `<link>` | просто ввести короткую ссылку - откроется исходный URL |
| `open <link>` | то же самое явной командой |
| `list` | мои ссылки: переходы/лимит, статус, сколько осталось жить |
| `edit <link> limit <n>` | поменять лимит (только владелец) |
| `edit <link> url <url>` | поменять исходный URL (только владелец) |
| `delete <link>` | удалить ссылку (только владелец) |
| `user` | показать мой UUID |
| `user new` | начать как новый пользователь (создает новый UUID) |
| `user <uuid>` | переключиться на другого пользователя |
| `help`, `h` | список команд с примерами |
| `exit`, `quit` | выход |

Ссылку можно указывать как `clck.ru/abc123` или `https://clck.ru/abc123`. В `open`, `edit` и `delete` можно писать и просто код `abc123`, а вот голый код в приглашении не сработает - это будет `Unknown command`.

Исходный URL должен начинаться с `http://` или `https://` и быть без пробелов (пробел кодируется как `%20`). Порт, если указан, должен быть от 1 до 65535. Домены не латиницей (IDN, например `пример.рф`) не поддерживаются, такой URL надо передавать в punycode (`xn--e1afmkfd.xn--p1ai`).

Пример сессии: первый пользователь создает ссылку на 2 перехода, второй ее исчерпывает, а уведомление ждет владельца и выводится, когда он снова становится текущим:

## Уведомления

Когда переход исчерпал лимит или ссылка протухла, уведомление кладется в очередь ее владельца и сразу пишется в `data/notices.tsv`, так что переживает перезапуск. Показывается оно только владельцу, когда он текущий пользователь: сразу после старта или переключения на него (`user <uuid>`), а если уведомление пришло, пока он сидит в приглашении (например, ссылку удалил планировщик), то после его следующей команды. Если за консолью сейчас другой пользователь, он уведомление не увидит, и UUID владельца тоже. Показанное уведомление удаляется из файла.

Протухшие ссылки удаляет планировщик, даже если к ним никто не обращается. Первый проход делается при старте до приветствия, поэтому про ссылки, которые протухли, пока программа была выключена, владелец узнает сразу.

## Конфигурация

Значения по умолчанию зашиты в jar (`src/main/resources/shortener.properties`). Поверх них читается внешний файл: путь из первого аргумента, а без аргумента `shortener.properties` из текущей директории, если он там есть. Внешний файл перекрывает только указанные в нем ключи, незнакомый ключ (например, с опечаткой) считается ошибкой.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `link.prefix` | `clck.ru/` | префикс коротких ссылок, без пробелов |
| `link.ttl` | `P1D` | время жизни ссылки (ISO-8601: `PT1H` - час, `P1D` - сутки), от `PT1M` до `P3650D` |
| `link.limit.default` | `10` | лимит переходов, если не указан в `shorten` |
| `link.limit.max` | `1000` | максимальный лимит |
| `url.max-length` | `2048` | максимальная длина исходного URL |
| `code.length` | `7` | длина кода (4-32) |
| `code.attempts` | `10` | сколько раз пробовать сгенерировать свободный код |
| `cleanup.period` | `PT1M` | как часто планировщик удаляет протухшие ссылки, от `PT1S` до `P1D` |
| `storage.links` | `data/links.tsv` | файл со ссылками |
| `storage.user` | `data/user.id` | файл с UUID текущего пользователя |
| `storage.notices` | `data/notices.tsv` | файл с непоказанными уведомлениями |

Все три пути `storage.*` должны указывать на разные файлы. Значения проверяются при старте: если что-то не так, программа пишет, какой ключ кривой, и завершается с кодом 1. Так же она завершается, если конфиг или файлы данных не читаются (например, не в UTF-8 или битая строка), и пишет, какой файл виноват.

## Архитектура

Три слоя, зависимости идут только внутрь (cli и infra знают про core, core ни про кого):

```
io.github.katehok.shortener
├── Main            сборка всех зависимостей руками (DI без фреймворка)
├── core            бизнес-логика без ввода/вывода
│   ├── ShortLink           ссылка: код, url, владелец, лимит, переходы, срок
│   ├── LinkService         сокращение, переход, правка, удаление, чистка по TTL
│   ├── ShortenerException  ошибка с причиной (enum Reason)
│   ├── Settings            параметры из конфига, нужные сервису
│   ├── CodeGenerator       генерация кода (случайный base62)
│   └── LinkRepository, NoticeStore, Notifier, Browser, UserStore   интерфейсы для внешнего мира
├── infra           реализации интерфейсов
│   ├── Config              чтение .properties с валидацией
│   ├── MemoryLinkRepository, FileLinkRepository   хранение ссылок в памяти / в файле
│   ├── MemoryNoticeStore, FileNoticeStore         хранение уведомлений в памяти / в файле
│   ├── FileUserStore       запоминание UUID
│   ├── CleanupScheduler    фоновое удаление протухших ссылок
│   └── DesktopBrowser      открытие URL через java.awt.Desktop
└── cli             консольный интерфейс
    ├── Cli                 разбор команд, help, сообщения об ошибках
    └── NoticeBox           текст уведомлений, хранит их через NoticeStore
```

Сервис зависит только от интерфейсов, поэтому в тестах хранилище подменяется на память, часы на управляемые, а браузер и уведомления на заглушки.

### Решения

- **Генерация кода.** 7 случайных символов из `[0-9A-Za-z]` через `SecureRandom`, плюс проверка по хранилищу и повтор, если код занят. Это 62^7 (около 3.5 * 10^12) вариантов, и коды уникальны глобально, поэтому у разных пользователей ссылки на один URL всегда разные. Хэш от URL не подходит: одинаковые URL давали бы одинаковый код. Счетчик тоже не подходит: коды шли бы подряд и их было бы легко перебрать. Коды удаленных ссылок не резервируются, но шанс, что новый код совпадет со старым, около 1/62^7, так что этим можно пренебречь.
- **TTL.** Проверяется в двух местах: при каждом обращении к ссылке (протухшая никогда не откроется) и в планировщике `ScheduledExecutorService` раз в `cleanup.period` (удаляет и уведомляет, даже если к ссылке никто не обращается). Время берется из `java.time.Clock`, который передается в сервис, поэтому в тестах час или сутки проматываются без `sleep`.
- **Лимит.** Переход, который исчерпал лимит, проходит, и владельцу сразу приходит уведомление. Следующие переходы блокируются. Если владелец поднимет лимит, ссылка снова заработает. Новый лимит должен быть больше уже сделанных переходов.
- **Права.** Все проверки владельца сделаны в `LinkService`, а не в CLI, так что их не обойти из другого интерфейса. Авторизации нет по условию задачи: UUID работает как ключ доступа, его надо хранить.
- **Потоки.** Планировщик работает в своем потоке, поэтому публичные методы сервиса `synchronized`.
- **Хранение.** Ссылки и уведомления держатся в памяти и при каждом изменении целиком пишутся в TSV-файл: сначала во временный, потом атомарный `move`, чтобы при падении не остаться с битым файлом. Если запись не удалась, память перечитывается с диска, так что неудачный `shorten` не оставит ссылку-сироту, а неудачный переход не засчитается. В сообщении об ошибке видно файл и причину, например `Couldn't save data: Couldn't write data/links.tsv (Permission denied)`.

## Тестирование

```bash
./mvnw test
```

168 тестов на JUnit 5:

- **unit**: `core` (генератор кодов, модель ссылки, все ветки `LinkService`), `infra` (конфиг, файловые хранилища ссылок и уведомлений, UUID, планировщик), `cli` (каждая команда и ошибки), `Main` (`--help`, сообщения при битом конфиге и файлах данных, уведомление о ссылке, протухшей пока программа была выключена)
- **интеграционные** (`ScenarioTest`), сценарии из ТЗ прогоняются через консольный интерфейс целиком:
  - один URL от разных пользователей дает разные короткие ссылки
  - после исчерпания лимита переход блокируется, владелец получает уведомление, а другой пользователь его не видит
  - ссылка удаляется по TTL в 1 час и в 1 сутки: и при обращении к ней, и планировщиком, когда к ней никто не обращается
  - после перезапуска (новый сервис на тех же файлах) пользователь и ссылки на месте, переходы считаются дальше
  - уведомление для другого пользователя переживает перезапуск и показывается ему один раз, когда он становится текущим
  - пользователь получает сообщение о недоступности с предложением создать новую ссылку
  - полный цикл `run()` на заранее заданном вводе

`DesktopBrowserTest` выполняется только в окружении без графики (например, в CI), на десктопе он пропускается.

## Качество кода и CI

- `.editorconfig` - отступы, кодировка, переводы строк
- Spotless - проверка форматирования: `./mvnw spotless:check` (или `./mvnw -Plint verify`, тогда проверка идет вместе со сборкой)
- Компилятор с `-Xlint:all` и `failOnWarning`: любое предупреждение ломает сборку
- GitHub Actions (`.github/workflows/ci.yml`): на каждый push в любую ветку и на каждый pull request в main - линт, сборка и тесты на JDK 25
